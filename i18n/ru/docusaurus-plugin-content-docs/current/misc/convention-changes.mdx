# Как меняется система конвенций H-Group

> **Важно:** эта страница описывает процесс принятия изменений в **оригинальной upstream H-Group**. Это не инструкция по сопровождению H-Group RU и не правила внесения изменений в этот русский репозиторий.

Набор conventions, с которым заранее согласна группа, называется _Convention Framework_. Он развивается со временем: появляются новые стратегии, старые перестают использоваться, существующие меняются.

## Кто может предлагать изменения?

- Предложить новый move или изменение convention может любой участник — и новый, и давний.
- При этом группа просит сначала хорошо освоить общий стиль игры, прежде чем активно предлагать изменения; в исходном документе ориентиром называется примерно max level.

## Как предлагаются изменения?

- Для предложений используется форум `#convention-proposals` в [Discord H-Group](https://discord.gg/FADvkJp).
- Для каждого предложения создаётся отдельный post.
- Обычно достаточно коротко описать изменение; истории с Alice и Bob приветствуются, потому что помогают быстро понять конкретную игровую ситуацию.
- Другие игроки обсуждают идею: нравится ли она им, какие видят проблемы и побочные эффекты.

## Нужно ли быть экспертом, чтобы участвовать в обсуждении?

Нет. Игрокам среднего уровня и выше предлагается читать свежие proposals и участвовать в обсуждениях, если им вообще интересна такая мета-работа над framework.

## Сколько обсуждается изменение?

Решения обычно не принимаются мгновенно:

- framework хотят менять сравнительно медленно;
- не все регулярно читают Discord, поэтому нужно оставить время для разных мнений.

Срок зависит от масштаба:

- маленькое и не вызывающее споров изменение иногда можно внедрить почти сразу;
- для заметных изменений обычно ждут дольше;
- явный широкий consensus сокращает период обсуждения.

## Что определяет, будет ли изменение принято?

Все изменения conventions принимаются через **group consensus**.

При оценке consensus мнения участников имеют условный разный вес. Исходный документ перечисляет факторы от наиболее к наименее важным:

1. воспринимаемый уровень мастерства;
2. целостное знание Convention Framework;
3. текущая активность — например, насколько часто человек сейчас играет;
4. сколько времени он играет с группой;
5. сколько игр сыграл с группой;
6. насколько регулярно участвует в обсуждении conventions.

Определение consensus **неизбежно в какой-то мере субъективно**. При ничьей или очень близком решении предпочтение отдаётся сохранению существующего framework без изменения.

## А если proposal почти никто не обсуждает?

Многие предложения получают мало внимания, но спустя время всё равно требуется принять решение.

- Если изменение крупное или потенциально спорное, consensus могут собрать вручную: написать нескольким наиболее сильным участникам и спросить их мнение.
- Если изменение небольшое и ни у кого нет сильной позиции, Zamiel обычно принимает практическое решение сам.

## Насколько быстро меняется framework в целом?

Медленно — обычно на масштабе месяцев. Это позволяет адаптироваться игрокам, которые играют только время от времени, например по выходным.

## Как объявляются новые conventions?

- Изменения объявляются через Discord-канал `#convention-announcements`.
- Практически каждое изменение публикуется там, кроме совсем мелких и незначительных.
- Обычно announcement появляется примерно одновременно с обновлением сайта.
- При этом публикуется не больше двух-трёх convention changes в неделю, чтобы не перегружать игроков, которые не хотят ежедневно читать про изменения framework.
- Если за неделю изменений больше двух-трёх, лишние попадают в announcement backlog и объявляются на следующей неделе.
- Если backlog становится достаточно длинным, до announcement конкретной convention может пройти довольно много времени; игроки, которые не читают GitHub issues регулярно, могли отдельно проверять backlog как быстрый список недавних изменений.

Упомянутый в upstream `announcement-backlog.md` — внутренний служебный материал H-Group, поэтому H-Group RU не публикует его как отдельную пользовательскую страницу.

## Насколько постоянны принятые изменения?

Ни одно изменение не является вечным: если consensus группы меняется, framework тоже может измениться.

Но постоянное переключение convention «включили сегодня — выключили завтра» особенно запутывает людей, которые играют нерегулярно. Поэтому H-Group старается не устраивать flip-flop.

Общее правило исходного документа: если по конфигурации convention уже достигнут consensus, не стоит снова открывать тот же вопрос примерно **в течение года**.

## Почему conventions удаляют?

Редко используемые conventions со временем удаляются и из framework, и с сайта. Есть две причины:

- каждый move и каждый раздел документации имеет цену в виде дополнительной сложности; он оправдан только тогда, когда приём действительно регулярно используется. Подробнее — [«Цели системы конвенций H-Group»](convention-goals.mdx);
- сайт задуман как **живое описание того, как группа реально играет сейчас**, а не как энциклопедия всех когда-либо придуманных Hanabi moves.

Решение о том, достаточно ли часто используется convention, чтобы оставаться в framework, тоже принимается через consensus.
