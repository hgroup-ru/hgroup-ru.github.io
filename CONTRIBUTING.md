# Как внести изменение

## Обычный процесс

Для внешнего участника достаточно:

1. сделать fork репозитория;
2. создать отдельную ветку;
3. внести изменение;
4. по возможности запустить локальные проверки;
5. открыть Pull Request;
6. исправлять замечания CI и review в той же ветке.

Мейнтейнеры тоже работают через отдельные ветки и Pull Request. Обычные изменения напрямую в `main` не отправляются.

## Куда отправлять правку

В этот репозиторий относятся:

- русский перевод;
- русская терминология;
- интерфейс и поиск русской версии;
- локальные Training Questions;
- явно обозначенные локальные учебные диаграммы.

Правки оригинального английского текста H-Group, игровой семантики, официальных YML-файлов и официальных диаграмм следует предлагать в [`hanabi/hanabi.github.io`](https://github.com/hanabi/hanabi.github.io).

Если ошибка исходного проекта уже видна в русском переводе, предпочтительно сначала исправить её в исходном проекте. H-Group RU не должен незаметно превращаться в самостоятельную редакцию правил. Небольшое число осознанных исключений перечислено в [`localization/SOURCE_EXCEPTIONS.md`](localization/SOURCE_EXCEPTIONS.md).

После принятия исправления в исходный проект мы обновляем закреплённую версию источника и соответствующий русский материал.

## Кандидаты на исправления исходного проекта

Во время перевода иногда обнаруживаются ошибки или улучшения, которые полезны не только русской версии: противоречия в тексте, устаревшие инструкции для внешних сервисов, улучшения общих компонентов или диаграмм.

Такие находки собираются в [`localization/UPSTREAM_CANDIDATES.md`](localization/UPSTREAM_CANDIDATES.md). Любой участник может выбрать пункт, проверить его по текущей версии исходного проекта и подготовить Pull Request туда.

`SOURCE_EXCEPTIONS.md` и `UPSTREAM_CANDIDATES.md` решают разные задачи: первый файл описывает уже существующие осознанные отличия русского текста, второй — возможные исправления и улучшения для исходного проекта.

## Локальная установка

Нужны Git, Node.js LTS и npm.

```bash
npm ci
npm run start
```

`npm run lint` также использует `yamllint` и ShellCheck. Если этих программ нет локально, CI всё равно выполнит проверку в Linux-окружении.

## Проверки

Для большинства изменений достаточно:

```bash
npm run lint
```

Если правка затрагивает MDX, YML или рендеринг страниц, полезно дополнительно проверить сборку русской версии для публикации:

```bash
npm run build:ru
```

`npm run build` собирает все настроенные локали. Для обычной работы над русской версией он не нужен.

Для Pull Request из внешнего форка CI автоматически запускает и lint, и `build:ru`, чтобы ошибки сборки были видны до слияния.

## Как работать с переводом

Закреплённая версия [`hanabi/hanabi.github.io`](https://github.com/hanabi/hanabi.github.io) — источник игрового смысла, структуры материала и официальных YML-файлов. Точная версия записана в [`upstream.json`](upstream.json).

При содержательном изменении русской страницы:

- сверяйтесь с соответствующим английским MDX/YML;
- сохраняйте все условия, исключения, примеры, предупреждения и обоснования;
- сохраняйте силу формулировок: обязательность, рекомендацию и возможность нельзя менять местами;
- не добавляйте новые игровые правила от себя;
- не сокращайте повторяющееся объяснение только потому, что оно кажется лишним;
- учитывайте, что более поздний Level может намеренно уточнять правило из более раннего материала.

Дополнительные правила собраны в [`localization/README.md`](localization/README.md), а принятая терминология — в [`localization/TERMINOLOGY_RU.md`](localization/TERMINOLOGY_RU.md).

## Диаграммы

Официальные диаграммы должны использовать YML из закреплённой версии исходного проекта и штатный плагин H-Group. Не восстанавливайте официальную диаграмму вручную по описанию в тексте.

В проекте также есть семь локальных учебных YML-диаграмм. Они не являются официальными диаграммами H-Group; список приведён в [`localization/README.md`](localization/README.md).

## Training Questions и Official Challenge Questions

Локальные Training Questions созданы для русской версии и не являются Official Challenge Questions. Не смешивайте эти категории в тексте, интерфейсе и описании изменений.

## Язык документации

Документацию проекта по умолчанию пишем на русском. Английские слова оставляем там, где это оправдано: в командах, именах файлов и API, названиях элементов интерфейса и формальных терминах H-Group.

## Лицензирование вкладов

Условия распространения описаны в [`LICENSE`](LICENSE) и [`LOCALIZATION_NOTICE_RU.md`](LOCALIZATION_NOTICE_RU.md). Отправляя Pull Request, участник подтверждает, что вправе предоставить свой вклад и разрешает распространять его на тех же условиях, которые применяются к соответствующему материалу репозитория (`CC BY-SA 4.0`, если для конкретного файла явно не указано иное).

Не добавляйте сторонний текст, изображения, данные или код, если у проекта нет права их распространять. Если материал имеет отдельную лицензию или требует атрибуции, укажите источник и условия в Pull Request.
