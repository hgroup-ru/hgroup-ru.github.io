## Цель и границы

Проверка сопоставляет последовательные production source SHA из `CHANGELOG.md` с фактическими изменениями между ними и с архивными пользовательскими release notes. Внутренние CI/release-maintenance, QA-инфраструктура и housekeeping не считаются обязательными пользовательскими пунктами release notes.

GitHub connector не предоставляет доступ к Release API/body для этого репозитория. Поэтому состояние опубликованных GitHub Release bodies подтверждается только там, где оно явно зафиксировано в PR-истории. Это ограничение не мешает проверить фактический production diff и текущий архивный `CHANGELOG.md`, но не позволяет задним числом объявить каждый старый Release body полностью синхронизированным.
