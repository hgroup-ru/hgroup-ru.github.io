# Кандидаты на улучшения upstream

Этот файл — публичный список изменений, обнаруженных при переводе и сопровождении H-Group RU, которые потенциально полезно предложить официальному проекту [`hanabi/hanabi.github.io`](https://github.com/hanabi/hanabi.github.io).

Задача списка — не создавать отдельный fork правил, а помогать возвращать полезные исправления и общие улучшения обратно в upstream. Любой участник может взять пункт, проверить его против актуального upstream и подготовить Pull Request туда.

## Что сюда попадает

- ошибки и противоречия оригинального текста;
- устаревшие инструкции по внешнему UI или сервисам;
- улучшения общих UI-компонентов сайта, обнаруженные при локализации;
- диаграммы или renderer-улучшения, которые имеют смысл для официального проекта, а не только для RU;
- другие отличия или локальные наработки, которые после проверки полезнее сделать общими.

Не каждый RU-specific элемент обязан становиться upstream-изменением. Локальные Training Questions, локальная терминология, RU search policy и другие явно локальные материалы остаются здесь, если у них нет самостоятельной ценности для официального проекта.

## Статусы

- `candidate` — идея зафиксирована, нужна проверка актуального upstream;
- `ready` — проблема/идея подтверждена и достаточно описана для upstream PR;
- `submitted` — upstream PR открыт;
- `accepted` — изменение принято upstream, после sync пункт можно удалить из активного списка;
- `declined` — upstream не принял изменение или оно больше не актуально.

## Текущие кандидаты

### Level 23 — Blaze Discard: Cathy → Alice

- **Статус:** `candidate`
- **Тип:** source correction
- **Суть:** в одном шаге закреплённого upstream пример переключает перспективу с Cathy на Alice, хотя рассуждение продолжает относиться к Cathy.
- **RU сейчас:** сохраняет Cathy; см. `SOURCE_EXCEPTIONS.md`.
- **Перед PR:** проверить, не исправлено ли это уже в текущем upstream.

### Level 24 — «3-player game» при четырёх названных игроках

- **Статус:** `candidate`
- **Тип:** source correction
- **Суть:** Example 3 называет Alice, Bob, Cathy и Donald, но одновременно описывает ситуацию как `3-player game`.
- **RU сейчас:** использует формулировку «в игре на четверых»; см. `SOURCE_EXCEPTIONS.md`.
- **Перед PR:** проверить актуальный upstream и контекст примера.

### `how-to-join` — актуализировать Discord microphone/PTT flow

- **Статус:** `candidate`
- **Тип:** external UI documentation
- **Суть:** закреплённый upstream использует устаревший шаг `Output Device`; RU следует проверенному актуальному flow `Input Device` / `Mic Test` / `Input Mode` -> `Push to Talk` -> `Edit Keybind`.
- **RU сейчас:** использует актуальный flow; см. `SOURCE_EXCEPTIONS.md`.
- **Перед PR:** ещё раз проверить текущий Discord UI и wording непосредственно перед отправкой upstream PR.

## Как добавить новый пункт

Для нового кандидата достаточно указать:

1. где обнаружено отличие или улучшение;
2. почему оно полезно upstream, а не только RU;
3. текущее поведение RU, если оно уже отличается;
4. что нужно перепроверить перед upstream PR;
5. текущий статус.

Если изменение уже активно влияет на RU и сознательно расходится с закреплённым source, одновременно обновите `SOURCE_EXCEPTIONS.md`.
