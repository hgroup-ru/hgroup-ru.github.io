# Кандидаты на исправления и улучшения исходного проекта

Во время перевода и сопровождения H-Group RU иногда обнаруживаются ошибки или улучшения, которые могут быть полезны официальному проекту [`hanabi/hanabi.github.io`](https://github.com/hanabi/hanabi.github.io).

Этот список нужен, чтобы такие находки не терялись. Любой участник может выбрать пункт, проверить его по текущей версии исходного проекта и подготовить Pull Request туда.

Для проработанных кандидатов подробные проверки и план подготовки Pull Request хранятся в [рабочих карточках](upstream-candidates/README.md).

## Что сюда попадает

- ошибки и противоречия в оригинальном тексте;
- устаревшие инструкции для внешних интерфейсов и сервисов;
- улучшения общих компонентов сайта, замеченные во время локализации;
- диаграммы или улучшения их рендеринга, полезные не только русской версии;
- другие локальные наработки, которые разумнее сделать общими.

Материалы, полезные только русской версии, сюда добавлять не нужно.

## Статусы

- `candidate` — находка зафиксирована, но её ещё нужно проверить по текущей версии исходного проекта;
- `ready` — проблема подтверждена и достаточно описана для подготовки Pull Request;
- `submitted` — Pull Request в исходный проект открыт;
- `accepted` — изменение принято;
- `declined` — изменение отклонено или больше не актуально.

## Текущие кандидаты

### Level 23 — ошибочная смена Cathy на Alice

- **Статус:** `candidate`
- **Суть:** в одном шаге закреплённой версии исходного проекта пример переключает перспективу с Cathy на Alice, хотя рассуждение продолжает относиться к Cathy.
- **Русская версия:** сохраняет Cathy; см. [`SOURCE_EXCEPTIONS.md`](SOURCE_EXCEPTIONS.md).
- **Карточка:** [подробный план проверки и PR](upstream-candidates/level-23-cathy-alice.md).
- **Перед Pull Request:** проверить, не исправлено ли это уже в текущем исходном проекте.

### Level 24 — `3-player game` при четырёх названных игроках

- **Статус:** `candidate`
- **Суть:** Example 3 называет Alice, Bob, Cathy и Donald, но одновременно описывает ситуацию как `3-player game`.
- **Русская версия:** использует формулировку «в игре на четверых»; см. [`SOURCE_EXCEPTIONS.md`](SOURCE_EXCEPTIONS.md).
- **Карточка:** [подробный план проверки и PR](upstream-candidates/level-24-player-count.md).
- **Перед Pull Request:** проверить текущий исходный текст и контекст примера.

### `how-to-join` — обновить инструкцию по микрофону и Push to Talk в Discord

- **Статус:** `candidate`
- **Суть:** закреплённая версия исходного проекта использует устаревший шаг `Output Device`; в русской версии инструкция соответствует актуальной последовательности `Input Device` / `Mic Test` / `Input Mode` → `Push to Talk` → `Edit Keybind`.
- **Русская версия:** использует обновлённую инструкцию; см. [`SOURCE_EXCEPTIONS.md`](SOURCE_EXCEPTIONS.md).
- **Карточка:** [подробный план проверки и PR](upstream-candidates/how-to-join-discord.md).
- **Перед Pull Request:** ещё раз проверить текущий интерфейс Discord и названия пунктов непосредственно перед отправкой изменения.

## Как добавить новый пункт

Укажите:

1. где обнаружена проблема или идея;
2. почему она полезна исходному проекту, а не только русской версии;
3. отличается ли уже русская версия;
4. что нужно перепроверить перед Pull Request;
5. текущий статус.

Если русская версия уже сознательно отличается от закреплённого источника, одновременно обновите [`SOURCE_EXCEPTIONS.md`](SOURCE_EXCEPTIONS.md).
