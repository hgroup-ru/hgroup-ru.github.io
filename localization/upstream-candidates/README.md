# Рабочие карточки для upstream-кандидатов

[`UPSTREAM_CANDIDATES.md`](../UPSTREAM_CANDIDATES.md) остаётся компактным реестром находок и их статусов. Этот каталог хранит подробные рабочие карточки для кандидатов, которые уже исследовались или которые планируется довести до Pull Request в официальный [`hanabi/hanabi.github.io`](https://github.com/hanabi/hanabi.github.io).

Карточка не заменяет проверку текущего upstream. Перед отправкой Pull Request нужно заново проверить актуальную версию исходного проекта: проблема могла быть уже исправлена, файл мог переместиться, а внешний интерфейс мог измениться.

## Когда создавать карточку

Не обязательно создавать отдельный файл для каждой сырой идеи. Карточка полезна, когда уже накопился контекст, который не хочется исследовать заново, либо когда кандидат готовится к переходу из `candidate` в `ready`.

## Что хранить в карточке

Обычно достаточно:

1. ссылки на запись в реестре и связанные материалы H-Group RU;
2. краткого описания проблемы;
3. того, что уже отличается в русской версии;
4. точного списка проверок перед Pull Request;
5. минимального предлагаемого изменения upstream;
6. ожидаемого scope файлов и проверок;
7. черновика заголовка или описания Pull Request, если он уже полезен;
8. после отправки — ссылки на Pull Request и его результата.

Не храните здесь secrets, private maintainer state, временные локальные пути или внутренние QA dumps.
